# Проверка seed 42 / 1024 и этапов обработки сетки

Проверена одна ранее неудачная картинка с камнями:
`.state/gui/inputs/b3d6d2ae357a49ab900abbaded7e9038.png`.
Исходный неудачный запуск: `outputs/20261016T165926Z_b5ba9197`.

## Условия

Два новых расчёта, каждый после свежего старта ComfyUI. Одна картинка,
Trellis2, форма 512, шаги 6/8/6, структура seed 56, 10000 целевых
треугольников, Remesh 256 UDF / smooth 1, текстуры 256, без AO и normal bake.
Менялись совместно seed формы и текстуры: 42/42 против 1024/1024.
Структура в обоих случаях принята с первой попытки: 2591 элемент при лимите 4096.
Автоматических повторов и смены seed в этом диагностическом запуске нет.

Скопирован существующий рабочий граф; изменения выполнены через рецепт
`comfy workflow apply`. Проверка API-графа разрешала менять только seed,
имя загруженной картинки и пути диагностических файлов. Добавлены три
ветки MeshToFile3D → Save3DAdvanced для выгрузки уже рассчитанных сеток.
Дополнительных sampler/VAE-проходов нет. Оригинальный workflow и настройки GUI
не изменены. Копия исходного workflow находится в `baseline.json` каждого запуска.

## Наблюдения

Оба seed дают узнаваемую исходную сетку камней. Большие визуальные повреждения
нужно оценивать по последовательности raw → remesh → decimate → final, а не по
последней текстурированной модели в одиночку. У обоих seed форма после Remesh
визуально сохраняется, после Decimate появляются большие стянутые треугольники.
Это локализует видимое ухудшение на этапе упрощения, но не доказывает, что
первопричина находится только внутри Decimate: важна и поступающая топология.

| Сохранённая стадия | Seed 42: треугольники | Seed 1024: треугольники |
| --- | ---: | ---: |
| После декодирования формы | 1 920 236 | 1 930 914 |
| После Remesh | 936 396 | 927 216 |
| После Decimate | 9 031 | 8 605 |
| Конечный GLB | 9 030 | 8 605 |

У seed 42 после Remesh измерено 0 граничных рёбер, после Decimate — 18
(после удаления одной вырожденной грани при последующей подготовке — 17).
Число граничных рёбер само по себе не является оценкой качества: остаются
немногообразные рёбра и возможны наложенные поверхности. Полные измерения
положений, площадей и рёбер сохранены в `analysis.json`.

Окончательные картинки отрисованы CPU-рендерером по исходным треугольникам,
без proxy-сетки, кластеризации или упрощения геометрии. Для ускорения исключены
только треугольники, чьи экранные bounding box не содержат ни одного центра пикселя.
На конечной сетке seed 42 результат побитно совпал с обычным рендерером:
`renderer-check.json`. Ракурс одинаковый (yaw 45°, elevation 15°), пропорции сохраняются.

Первоначальная сборка отчёта seed 42 ошиблась в именах скачанных файлов:
CLI переименовал их в `<prompt_id>_NNN.glb`. Сопоставление восстановлено по URL
из download.stdout.log и истории выходных узлов, без повторного GPU-расчёта.
Исходная ошибка сохранена в отчёте как postprocess_error, история ComfyUI — success.

Оба тестовых сервера завершены штатным проектным Stop-ComfyUI.ps1.
Исправления алгоритма упрощения по этому тесту пока не вносились.
