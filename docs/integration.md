# Запуск генерации из программы

`quality="fast"` в `generate_3d` / `Parameters` или `-Quality fast`
в PowerShell включает форму 512 и sampler 6 / 8 / 6, без Upsample 1024,
второго shape-sampler и дополнительных карт normal/AO. Для теста 1000
полигонов передавайте `remesh_resolution=128, texture_size=128`.
CLI/API по умолчанию сохраняют `quality="standard"` и режим топора.
Автоматический подбор размеров выполняет интерфейс; явные размеры API
остаются параметрами вызывающей программы.

Python-адаптер `dart3s.generate_3d` вызывает установленный локальный Comfy CLI:
загрузка изображения → сборка параметризованного рецепта → отправка → ожидание
задачи → скачивание. Адаптер использует уже работающий ComfyUI по адресу
`http://127.0.0.1:8188` или автоматически запускает установленный portable
ComfyUI скрытым процессом. Требуются установленные узлы/модели шаблона.

Из PowerShell в папке проекта:

```powershell
.\Generate-3D.ps1 -Image 'C:\path\source.png' -Model pixal3d -Polygons 10000 -RemeshResolution 256 -TextureSize 256
```

Для Trellis.2 используйте `-Model trellis2`. Общий seed формы задается
`-ShapeSeed 42`: сборщик подключает одно значение к обоим зависимым от формы
sampler-узлам. Отдельные seed структуры и текстуры — `-StructureSeed 56` и
`-TextureSeed 43`. Размер текстур квадратный и общий для PBR-карт.

`-NoStartServer` / `auto_start=False` отключает автоматический запуск сервера.
Ожидание готовности ограничено 180 секундами (`-StartupTimeout` /
`startup_timeout`). PID запущенного процесса сохраняется в `generation.json`,
логи сервера — в `logs/comfyui.stdout.log` и `logs/comfyui.stderr.log`.
Адаптер не завершает ранее запущенные серверы. Подготовка с `-PrepareOnly`
и `-ObjectInfo` выполняется без проверки или запуска сервера.

Сервер запускается через `scripts/comfy_server.py`: Windows-диалоги о сбоях
отключены для этого процесса, а `faulthandler` сохраняет стек в stderr-лог.
Так нативный сбой ROCm становится диагностируемой ошибкой запуска и не блокирует
программу модальным окном. Обращения к GPU выполняются без подмены API.

Из Python, импортируя модуль из этой папки:

```python
from dart3s import generate_3d

result = generate_3d(
    r"C:\path\source.png",
    model="pixal3d",
    polygons=10000,
    remesh_resolution=256,
    texture_size=256,
    shape_seed=42,
)
print(result.glb_path)       # абсолютный путь к существующему GLB 2.0
print(result.prompt_id)      # ID задания ComfyUI
print(result.metadata_path)  # параметры, этапы и ошибка, если она возникла
```

Функция синхронная: в графическом приложении вызывайте ее из рабочего потока.
Необязательный `progress` принимает событие-словарь при смене этапа. Во время
ожидания используется `comfy --json-stream jobs watch`; callback получает
`{"status": "generating", "event": ...}` с событиями `executing` и `progress`.
У `progress` поля `node`, `completed`, `total` дают реальный процент текущего
этапа. Без callback ожидание сохраняет обычный JSON-режим CLI. Результаты
и логи находятся в отдельной папке `outputs/<UTC-время>_<идентификатор>/`.
Можно передать `output_dir` / `-OutputDir`. Метаданные обновляются после
отправки задания, чтобы ID сохранился даже при обрыве соединения.

`visual_progress=True, preview_size=256` включает четыре узла наблюдения
готовых промежуточных данных. Допустимые размеры — 128, 256 и 512.
В интерфейсах Dart3s и Details3D промежуточный предпросмотр сейчас отключён
по просьбе пользователя: новые задания передают `visual_progress=False`,
узлы наблюдения и зависимость ранней сетки в граф не добавляются, монитор
картинок не запускается. Счётчик шагов, время, сигнал готовности и просмотр
итогового GLB продолжают работать. Описанный ниже режим остаётся доступен
для явного вызова через Python API.
Событие `building` и `generation.json` содержат `preview_directory`.
Клиент читает `latest.json` в этом каталоге: `revision`, `stage`, абсолютный
путь `image`, фактические `triangles`, `size`, время `created_at`.
Узлы передают исходные данные дальше; дополнительной генерации, VAE Decode
или GPU-отрисовки нет. При возобновлении задания используйте исходный
каталог предпросмотров из сохранённых metadata. GUI сохраняет его вместе с ID.

При включённом визуальном прогрессе зависимость `Dart3sGeometryReady`
задаёт порядок: декодирование сетки → серый предпросмотр → генерация
текстур. Remesh и упрощение остаются в прежней ветке перед UV-развёрткой
и запеканием; их серый кадр публикуется сразу по готовности. Перенос
GPU Remesh перед sampler текстур вызвал замедление в проверочном запуске,
поэтому ранняя зависимость ожидает только исходную декодированную сетку.
Узел возвращает тот же рассчитанный latent; дополнительные sampler/VAE
не запускаются. Без этой зависимости планировщик мог откладывать ветку
предпросмотра до окончания текстур, хотя геометрия уже была рассчитана.
Два серых кадра публикуются CPU-потоком с ограниченным ожиданием до 10 с
на кадр; при ошибке или тайм-ауте генерация продолжается. Структура и
текстурный кадр остаются асинхронными. Размер задаёт короткую сторону,
длинная рассчитывается по пропорциям модели, без растягивания.

CLI печатает итоговый JSON в stdout, сообщения об этапах — в stderr. Код выхода
0 означает подготовленный workflow или реально скачанный GLB; код 1 означает
ошибку. Поле `status` различает `prepared` и `completed`. При ошибке Comfy CLI
код, подсказка и детали сохраняются в `ComfyError` и `generation.json`.

Подготовка без загрузки изображения и запуска GPU:

```powershell
.\Generate-3D.ps1 -Image 'C:\path\source.png' -PrepareOnly -ObjectInfo '.\logs\object_info.json'
```

`-ObjectInfo` задает сохраненный каталог узлов для работы без сервера. Без него
сборщик читает каталог запущенного ComfyUI. В режиме подготовки workflow
ссылается на basename исходного файла; перед отдельным запуском этот файл должен
уже находиться в каталоге `input` ComfyUI.

Если ожидание прервалось, существующее задание может продолжать работу. Используйте
его ID из метаданных, чтобы продолжить ожидание и скачивание без повторной отправки:

```powershell
.\Generate-3D.ps1 -Resume '<prompt_id>'
```

В Python это `dart3s.resume_3d(prompt_id)`. `-WaitTimeout` / `wait_timeout`
задает ограничение ожидания клиента в секундах (по умолчанию 7200); таймаут не
отменяет задачу на сервере.

Адаптер всегда задает локальный маршрут `COMFY_WHERE=local`, принимает только
HTTP-адрес loopback и вызывает subprocess без shell. Состояние Comfy CLI хранится
в `.state` проекта, телеметрия отключена. Параметры workflow изменяются через
официальный `comfy workflow apply`, а не правкой экспортированного графа.

Текущий Comfy CLI не извлекает выходы из стандартного ключа `3d` узла
`Save3DAdvanced`. Адаптер читает метаданные завершенного задания через локальный
`/history`, преобразует SavedResult в адрес `/view` и передает этот адрес в
stdin команды `comfy download`. Скачивание по-прежнему выполняет Comfy CLI.
Исходная история сохраняется рядом с результатом в `history.json`.

Проверка и предпросмотр готового GLB:

```powershell
.\ComfyUI_windows_portable\python_embeded\python.exe .\scripts\verify_glb.py 'C:\path\model.glb'
.\ComfyUI_windows_portable\python_embeded\python.exe .\scripts\render_glb_preview.py 'C:\path\model.glb' --out 'C:\path\model.preview.png'
```

Первая команда проверяет геометрию и размеры встроенных текстур. Вторая создаёт
PNG из реальной геометрии и базовой текстуры на CPU, с простым освещением;
карты normal/AO/metallic/roughness в этом предпросмотре не используются.
Для полного просмотра материала откройте GLB в 3D-просмотрщике ComfyUI.

В локальной установке применены две небольшие правки Comfy CLI: Windows-путь
конфигурации учитывает `LOCALAPPDATA`, а запись обычных scalar-widget значений
обновляет существующую карту `widgets_values_named` вместе с массивом
`widgets_values`. Без второй правки CLI отправляет правильное значение, но
современный frontend при открытии workflow может восстановить старое значение
из карты по имени. Например, Upsample возвращался к 1536 вместо заданных 1024.
Оригиналы `constants.py` и `cql/engine.py` сохранены с суффиксом `.py.pre-dart3s`.
Скрипт проверяет известные участки исходного пакета перед изменением и безопасен
при повторном запуске; `--check` проверяет установку без записи.
После обновления Comfy CLI примените правки повторно:

```powershell
.\.venv-cli\Scripts\python.exe .\scripts\configure_cli.py
```

Проверка контрактов адаптера:

```powershell
.\.venv-cli\Scripts\python.exe -m unittest discover -s tests -v
```

Эти тесты проверяют изоляцию локального маршрута, ошибки CLI, сохранение ID,
а также очередь интерфейса (`tests/test_image_queue.py`, `scripts/test_queue_gui.py`).
Кнопка «Добавить картинки» принимает несколько файлов; вставка и повторный
выбор дополняют список, в том числе во время генерации. Стрелки меняют порядок
ожидающих изображений. «Запустить очередь» применяет текущие параметры ко
всей партии; следующее задание начинается после завершения предыдущего,
выгрузки весов и итогового CPU-предпросмотра. Промежуточный предпросмотр выключен.
Двойной щелчок по готовой строке показывает её результат. Один звуковой сигнал
подаётся после успешного завершения всей партии, если включён звук.
Список сохраняется в `.state/gui/queue.json`. Ошибка или остановка ставит
очередь на паузу. При потере соединения «Продолжить задание» использует уже
полученный prompt ID; повторная отправка этой модели не выполняется.
После закрытия окна сервер может закончить текущую модель, но запуск следующих
изображений требует открытого приложения. Ожидающие картинки сохраняются.

«Остановить» посылает обычное прерывание текущего задания. Если ожидание
затягивается, «Прервать сразу» после подтверждения завершает процесс ComfyUI
этого проекта на порту 8188, убирает текущую строку и сохраняет остальные.
Все задания этого экземпляра сервера прерываются. Готовые GLB и исходные
картинки не удаляются; следующая генерация запускает ComfyUI заново.
Нажатие «Убрать» для работающей строки предлагает тот же вариант.
Операции CLI и ожидание прогресса поддерживают отдельный cancel_event;
устаревшие события старого worker не меняют новую очередь или pending.json.
Проверки: tests/test_cli_stream.py, tests/test_gui_jobs.py,
scripts/test_force_cancel_gui.py. Завершение сервера ограничено проверенными
PID с точным путём Python и wrapper проекта; другие процессы Python не затрагиваются.

Тесты адаптера также проверяют повторное подключение и выходной GLB. Проверка настоящего
`comfy workflow apply` с офлайн-схемой также сравнивает параметры для API и
восстановления холста, включая Upsample 1024, общие seed и размер текстур.
Они не заменяют GPU-проверку реальной генерации.

После скачивания валидного GLB адаптер проверяет `/queue`. При пустой очереди
отправляет `/free` с `unload_models=true`, `free_memory=false`: освобождаются
веса нейросетей, но процесс сервера, история и кеш выходов узлов сохраняются.
На RX 6600 после последовательных запусков обнаружены около 1,56 ГиБ
оставшихся GPU-весов; отдельная выгрузка уменьшила занятые PyTorch-тензоры
до 35 МиБ без новой генерации. Переход на `--cache-classic` проблему повтора
не устранил и в штатный запуск не добавлен.

Обслуживание выполняется рабочим потоком, показывает этап «Освобождаю
видеопамять», не посылает новое задание и не выполняется при тайм-ауте
наблюдения ещё работающей генерации. Занятая очередь пропускается. Сбой
endpoint записывается в `generation.json.memory_cleanup`, сохраняя успех GLB.
Ожидание наблюдаемого уменьшения памяти ограничено 12 секундами (плюс время
HTTP-запросов); `requested` означает принятие запроса без подтверждённого
снижения памяти, `release_observed` — снижение в показаниях `/system_stats`.
При менее 64 МиБ занятых PyTorch-тензоров и более 90% свободной VRAM
обслуживание пропускается со статусом `already_released`.
Контрольная пара после изменения: тот же топор, форма 512, шаги 6/8/6,
seeds 56/42/42, 10 000 треугольников, Remesh 256, текстуры 256×256.
Без перезапуска сервера первый расчёт занял 95,016 с, второй — 93,450 с;
sampler структуры — 35,637 и 35,379 с. В исходной паре до очистки было
97,705 и 420,963 с. Проверены реальные sampler-проходы, оба GLB и снижение
занятых PyTorch-тензоров до 35 МиБ после завершения. Загрузка CPU за 10 с
простоя после второй генерации — 0%. Отчёт:
`logs/repeated-input-memory-cleanup/report.md`, независимые проверки —
`verification.json`, `resource-summary.json`, `idle-cpu.json` в той же папке.
Эта пара подтверждает устранение повторного замедления для указанного
изображения и режима; тяжёлый 1024 отдельно не проверялся.
